# 外观排版、标签操作与保存修复实施计划

> 执行方式：按已确认要求在当前项目内执行；保存修复和搜索定位由独立代理负责，主代理负责界面及整体验证。沿用项目内运行时，不移动业务数据、不新建依赖或开发服务器。完成后评审、提交并快进主分支。

## 已确认规格与边界

- 最新口径：所有按钮/选择框默认在第二行。各功能组靠上，第一行标题/说明占统一高度；内容需要两行、三行就自然分行，不垂直居中。
- 优先级与标签标题同一水平线；标签旁显示“（点击应用；已选标签可移除）”。
- 加粗、斜体、删除线、字体颜色、背景颜色同排5个；这排在字号上面，字号在下面。颜色主题、逻辑结构、链接、图片从第二行开始。
- 工具栏标签删除按钮悬浮在右上角，不挤占宽度；节点标签改圆角并提供悬浮删除单标签。标签组清除按钮移除当前选中节点标签。普通任务执行状态保持只读。
- 搜索第一个命中居中；他人持相关锁时任务编辑入口提示“源用例被锁定，不可编辑”，不能把自己持锁误报为不可编辑。
- 保存错误先定位：日志已确认resource字段缺失时却执行replace。修正责任层并保留未确认写入保护；禁止盲目重发、用快照覆盖新数据、自动刷新丢草稿。
- 后续补充：滚动条四端只对应当前展开可见节点的边界，折叠/展开后重新读取布局；手动平移出的空白不扩大滚动范围。折叠数字按钮半径由10缩至8，展开状态半径6保持不变，99及超99省略规则不变。
- 用户已确认当前未保存内容只有标签，同意部署后重新添加；不重放旧未知补丁。

## 架构与兼容审查

仅复用Minder Resource命令、现有视图恢复/布局完成契约、Socket锁及保存机制。渲染层不直接写库，标签删除仍通过Resource命令进入历史/自动保存。无数据库迁移和依赖升级。保存失败来源与未确认旧页面须分别验证，不能以消除提示冒充落库成功；业务服务在安全部署门禁前保持现状。
