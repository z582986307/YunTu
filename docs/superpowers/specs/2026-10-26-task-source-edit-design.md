# 测试任务中编辑源用例

## 已批准的目标

- 同一源用例可分成多个任务，多人并行执行；各任务的执行结果、执行备注和任务外观独立保存。
- 任务页增加“编辑用例 / 结束编辑”模式，可在当前位置连续修改节点、整个模块、层级、图片、链接、优先级和标签。
- 用例内容修改共用源用例房间的锁，普通任务执行继续使用各自任务房间的锁；同用户不同页面也按不同会话隔离。
- 任务内容编辑保存成功后写回源用例，其他已打开任务只显示更新通知，刷新后加载最新内容。
- 当前编辑者结束编辑无需手动刷新，自动返回最新任务内容，保留选择节点、缩放和画布位置；原节点已删时回到最近保留的父节点。
- 手动刷新任务也恢复上述位置；执行结果和备注按节点 ID 保留。
- 外观菜单补回优先级与标签设置；任务非内容编辑模式下不可修改源用例标记。
- 内容编辑支持与用例编辑相同的图片上传、粘贴、预览、调整尺寸、删除能力。

## 数据与组件边界

1. 源用例编辑仍由已有源用例 WebSocket 房间维护唯一内容、锁和版本。
2. 任务进入内容编辑时，先保存已确认的任务状态及视图，再以新的编辑器实例连接源用例房间，查询参数 `recordId=undefined, sourceTaskId=<任务ID>`。同一时间只挂载一个编辑器，避免现有 `window.minderData` 等全局状态混用。
3. 新实例复用完整用例编辑器，不拿经过任务筛选的脑图覆盖源用例。展示完整源用例，并淡化、说明未分配到当前任务的节点；任务筛选条件不因展开完整内容而改变。
4. 内容编辑实例显示源用例外观；任务独立外观在返回执行模式后恢复。内容编辑时不把任务的外观快照覆盖源用例。
5. `sourceTaskId` 必须在服务端验证属于当前源用例。进入内容编辑必须持有源用例锁；禁止内容模式中途通过开关释放锁，结束编辑/断开时释放。
6. 该模式提交的内容补丁按既有版本校验后，先持久化源用例，再确认成功。持久化失败恢复内存内容并向当前提交者明确报错；不通知其他任务成功更新。
7. 任务编辑器原实例卸载时释放自身任务房间连接。其他任务继续执行；若同任务有其他页面，可以按既有任务锁规则接管执行。返回时重新获取该任务的最新记录及权限，不假定仍持有任务锁。

## 刷新和通知契约

- 源用例有实际内容更新后，对关联的活动任务房间发送 `source_case_updated`，`message` 为源内容版本字符串。
- 已打开任务收到通知，仅展示“源用例已更新，刷新后查看”，不覆盖当前画面、不改变当前任务的执行版本、不误报自身编辑过期。
- 新连接进入任务房间时检查数据库源内容版本和固定长度内容摘要。即使手动外观保存造成同 base 的真实源内容变化，也使用最新源用例与已落库任务结果、备注、展开状态、独立外观重新合并；不改变普通源页既有保存应答语义。
- 同任务其他旧页面若因此与该房间快照不同，收到 `stale_data_event` 并使用已有刷新弹窗阻止旧快照继续提交；其他任务不受影响。
- 任务房间维护独立的 `sourceVersion`，不得把它与执行过程中递增的 `base` 混为一个版本。刷新房间时任务 `base` 单调递增，避免旧执行页误保存。
- 源用例普通自动/手动保存也发送同样更新通知，但无变化保存不发送。

## 前端保存与位置契约

- 编辑器提供 `saveAndWait(): Promise<void>`，沿用现有保存请求和确认；保存失败、版本冲突、连接关闭、卸载时拒绝，不虚报成功。
- 源模式历史命令的版本确认使用独立 `source_revision_event`，不消耗普通编辑的确认计数；等待前序编辑确认，并在历史确认前暂时禁止新内容命令，结束模式也等待该确认。
- 进入内容编辑前提交当前输入并等待在途任务编辑确认；结束编辑等待内容保存确认，再卸载源编辑器、回到任务模式。
- 保存等待包含图片粘贴/上传产生的异步操作；上传未完成不能结束模式，失败时提示且保留编辑态。
- 编辑器提供 `captureViewState()`，并通过 `initialViewState`、导入完成回调恢复节点 ID、祖先 ID、实际缩放比例和节点在屏幕上的锚点。以节点 ID 为主，原始平移为无节点时兜底。
- 当前任务页会话内使用 `sessionStorage` 保存不含正文、账号、Cookie、令牌的视图信息，键包含源用例 ID 和任务 ID；不同标签的执行位置互不污染。
- 持续编辑源用例时先保留原任务的视图，再更新来源；返回任务时采用源保存确认后的最新数据，不能恢复旧内容缓存。
- 节点已删除时按祖先 ID 顺序选择最近仍存在的父节点，否则中心主题兜底。
- 源模式载入锁拒绝时返回原任务位置并提示，不进入可写模式。

## 历史兼容及限制

- 不改数据库结构，不合并任务执行结果到源用例，不删除历史任务数据。
- 老版本网页通过已有平台版本检测要求刷新。
- 继续使用现有 React/Ant Design/Kityminder、Node 14 构建及 JDK 8，不升级依赖。
- 默认生产模式；测试使用项目内隔离目录和独立端口；本地业务数据库不能进入运行包。
- 新增标签入口复用现有 `TagGroup`，补齐必要边界与监听清理；优先级复用 `PriorityGroup`。

## 验收

1. 两个不同任务同时标记结果，互不覆盖；其中一个进入内容编辑，另一个仍可执行。
2. 用例页已持锁时任务不能内容编辑；任务内容编辑持锁时用例页不能编辑；结束/断开释放源锁。
3. 按标签/优先级筛选的任务修改完整模块后，未展示的源节点仍在，所有结果和备注不进入源用例。
4. 输入、图片粘贴/上传、修改层级、优先级、标签保存回源；当前任务返回后立即显示最新内容。
5. 他人任务只提示源更新，刷新后新内容及原执行结果、备注、独立外观都正确；旧版本提交被拒绝。
6. 编辑往返和手动刷新保留选中节点、缩放及位置；删除当前节点后回到最近父节点。
7. 保存失败时停留编辑模式并保留输入；无变化保存不触发其他任务更新提示。
8. 功能评审、前端测试、后端测试、生产构建、真实浏览器联动验证通过后，合并、推送、更新 Windows ZIP。
